## 待确认业务决策

| 编号 | 修订稿采用的方案 | 原因与影响 |
| --- | --- | --- |
| D01 | 离线即时显示 `PENDING` 预估星星，服务端确认后按 key 对账 | 保留儿童即时反馈；客户端须持久化奖励结算覆盖信息，不能只依赖事件 ACK |
| D02 | 词级/句级各 1 星；课程小游戏固定 1 星；今日完成每天必得贴纸；连续 3/7/14/30 天必得徽章 | 消除粗粒度 key 与概率奖励；徽章里程碑各领一次，MVP 不做消费扣星 |
| D03 | 学习日由儿童档案时区及其历史版本决定 | 设备时区不改业务归档；时区修改次日生效，历史不搬移 |
| D04 | 家长入口采用 4–6 位 PIN、NAS 限次与短期会话 | 定位为家庭防误触，长按和算术题不能代替验证；NAS 不可达时不新开管理会话 |
| D05 | 游戏入口为 `FREE`，课程内小游戏为 `COURSE` | 自由游戏不发星、不满足课程步骤、不计打卡，仍可记自由练习时长 |
| D06 | 麦克风权限被拒或不可用时，听完示范后可记 `SKIPPED` | 满足打卡但无该词/句星星；家长报告原因，补做录音按唯一 key 首次发星 |
| D07 | M0–M2 为首个可用版本，M3–M4 独立排期 | 本地事务、同步、幂等账本、HTTPS 与基本备份前置，内容和完整报告后续扩充 |

以上选择均已在正文按同一口径展开，供集中确认；未把评审意见直接描述为已生效规范。

## 一致性补充

这些补充用于让评审修订后的链路可实现，不表示新增实现已完成：

- 任务快照冻结内容、时区和规则版本；预生成未来 7 天，耗尽后仅自由复习，避免客户端伪造每日任务。
- `eventId` 同时校验归属和原始载荷摘要，避免同 ID 换数据被当成安全重复。
- 家庭同步流在事务内加行锁，确保提交顺序与 Pull 序列一致；单用数据库序列号可能漏掉晚提交的低号变更。
- Push 的 `serverCursor` 只作参考；本地 Pull 游标随持久化页推进，按每设备每儿童隔离。
- 游标过期用一致性完整快照恢复，同时保留未确认 outbox 和奖励，不直接清空端侧事实。
- 首次初始化、家长短期会话、配对码与设备撤销分别定义；离线不开放新的家长管理会话。
- 参考 SQL 和 Compose 不再声称有不存在的外部附件，也不作为已验证的迁移或部署脚本。
- 新增 T13–T22 计划用例；原 T01–T12 按新契约修订，没有把计划用例写成已通过。
