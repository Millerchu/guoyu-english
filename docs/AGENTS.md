# docs/ 文档协作指南

本目录继承 [根指南](../AGENTS.md)。文档服务于当前项目的实施、联调和验收，默认以中文 Markdown 维护。

## 资料与事实边界

- 先阅读 [文档索引](README.md)。正式 V1.7 Word 位于 [设计文档/guoyu-english-detailed-design-v1.7.docx](设计文档/guoyu-english-detailed-design-v1.7.docx)，不要改用当前并不存在的 `design/` 路径。
- [design-review-v1.7.md](design-review-v1.7.md) 为评审意见，建议与判断须和已确认结论区分，不直接改写成生效规范。
- 指南建立时尚无正式 API、迁移 SQL、开发指南、路线图或测试矩阵文件；创建后同步更新索引和实际状态。
- V1.7 是设计版本。没有源文件、构建产物或运行记录，不写成已发布版本、已实现接口或已通过验收。
- 已有说明、设计和实现冲突时，先列明各自证据与当前影响；不机械规定“文档永远正确”或“代码永远正确”，也不擅自用另一套术语覆盖。

## 内容与组织

- 文档开头交代用途、适用版本、范围和结论，再给读者需要的细节。用真实路径、字段、变量示例和验收条件说明问题，省略无助于使用的过程流水账。
- 设计、接口、数据库、部署、测试各自维护职责，索引链接互通；避免复制完整章节后多处漂移。
- 修订 API 时记录路径、方法、身份、请求/响应、错误码、时间与分页语义、幂等与兼容策略；不能只列端点名。
- 修订同步协议时说明 eventId、逐条 ACK、批量限制、失败重试、服务端游标、设备撤销、儿童归属与资源包版本。
- 修订数据库时区分概念模型、参考 SQL 与已执行的 Flyway 迁移，记录约束和事务语义；参考 SQL 不自动等于可部署脚本。
- 涉及尚有争议的奖励 key、离线奖励、学习日时区、跳过录音、游戏入口和时长统计时，注明决策状态、受影响范围及验收口径，不自行拼接相互冲突的章节。
- 有意义的设计决策记录原因、最终选项与影响，关联实施文件；不因所有设计尚未统一而暂停无关文档整理。

## 编写与文件维护

- 默认增量修改现有文件，不整体覆盖用户定制内容。技术标识符与实际代码一致，不硬套 Foundation、MRO 或其他项目术语。
- 修改已有 Word、PDF 等定版资料先明确任务范围，保留原件；无需为普通 Markdown 更新重新生成大体积二进制文档。
- 新建阶段性改造说明、诊断报告或验收记录时可采用 `YYYYMMDD-主题.md`；持续维护的索引、API、开发指南等使用稳定文件名。
- 若要求技术社区分享，讲清“思路、设计、关键实现/详细改造代码”，在需要的位置保留明确截图占位；参考源码包与补丁制作单独按请求交付。
- Markdown 使用 UTF-8，中文路径保持可用；链接只指向真实文件。规划中的资料用待补文字描述，不用失效链接伪装现有产物。
- 图片、原型、素材和参考项目标明来源；不得写入真实儿童身份、录音、家庭地址、PIN、密钥或未脱敏日志。

## 核验与交付

- 校验标题层次、表格、代码块、相对链接、设计版本、配置项和命令前提；根 README 中已有的坏链不因此视为合理范例。
- 示例与真实验证记录分开；命令附执行目录和必要前置条件，未执行的命令不标记成功。
- 自动检查或文档链接检查只证明相应检查通过，不能代替 Maven/npm 构建、数据库验证、设备或 NAS 验收。
- 检查 `git diff --check`，并单独检查新文件。交付列出实际生成路径、主要内容与未验证部分；默认不提交 Git。
