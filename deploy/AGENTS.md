# deploy/ 部署协作指南

本目录继承 [根指南](../AGENTS.md)。阅读 [部署说明](README.md)，并核对服务端与客户端实际产物后再修改部署配置。

## 现状与目标

- S03 已加入 `docker-compose.yml`、`.env.example`、Nginx 配置，以及服务端和 H5 的镜像构建文件。这是本机可检查的编排，不是家庭 NAS 已验收，也不是公网入口。备份脚本仍留给 S21，恢复未验证。
- 目标是家庭 NAS 上的 PostgreSQL 16+、Spring Boot 服务、Nginx H5 / API / 媒体入口，可按需要加入备份任务。
- NAS 挂载路径、CPU 架构、可用端口和证书能力需实际核对；`/volume/docker/guoyu-english` 是示例，不能当成当前用户真实路径。

## 配置与网络

- 仅提供家庭局域网入口，默认不做公网映射，不自动修改路由器、UPnP、防火墙或 NAS 安全设置。
- 数据库仅在容器内部网络，不向宿主机发布 5432；服务端通过内部网络连接数据库，统一由入口代理提供服务。
- H5 录音与 Service Worker 使用设备信任的 HTTPS，检查证书链、域名和实际平板访问结果；服务可 HTTP 访问不等于录音能力已验收。
- `/api` 反代与后端 `/api/v1` 保持一致，检查是否错误截断或重复前缀；H5 路由回退、媒体路径、MIME 与缓存策略分别验证。
- `.env.example` 只放变量名和安全占位值，真实 `.env`、密码、令牌、证书私钥及签名材料不入库，也不出现在日志或说明输出中。
- 环境变量与后端配置绑定一致，区分 NAS 宿主机路径、容器内路径和浏览器 URL，避免混写。
- 固定可追溯的镜像版本及适配的 CPU 架构，不依赖浮动 `latest` 作为可重复部署依据。
- 数据、媒体和必要日志持久化；公开课程素材只读挂载，录音上传需要单独规划可写目录、权限、配额与清理。

## 启动、升级与恢复

- 实际配置形成后，先进行 Compose 配置检查，避免把插值后的真实密钥输出到聊天或公开文件；配置通过不代表容器或服务已经健康。
- 数据库健康检查使用匹配镜像能力，例如 `pg_isready`；服务端等待数据库健康，并保留合理重试，不仅依赖容器启动顺序。
- 健康检查只返回必要的可达性与版本信息，不暴露数据源密码、设备信息或其他内部配置。
- 升级前记录当前镜像、配置和迁移版本，备份 PostgreSQL 与媒体清单；备份放在与数据库数据目录不同的位置，并规划外部副本。
- Flyway 不等于可自动回滚。恢复方案同时考虑旧镜像与新 schema 是否兼容，不能简单以“重启旧镜像”代替数据恢复。
- 不执行 `docker compose down -v`、删除数据卷、清库、覆盖备份或对真实 NAS 做升级/恢复演练，除非用户明确授权相应操作。
- 实际部署、推送镜像、修改 NAS 和运行恢复脚本与本地编写配置区分；先准备可审查配置和验证记录，再按用户已授权范围执行。

## 验证与交付

- 本地静态检查、镜像构建、容器启动、健康检查、真实 NAS、Android / H5 联调分别记录结果，不相互代替。
- 拓扑验收检查数据库未暴露、HTTPS 可用、API 前缀正确、媒体可读、服务重启后数据仍在。
- 联调至少覆盖设备配对、下载资源包、NAS 不可达时学习、恢复连接后同步，以及重复 Push 不重复发奖。
- 备份恢复在隔离位置验证记录、奖励与媒体清单完整性；未真实恢复过就标记“恢复未验证”。
- 交付说明列出实际文件、环境变量、宿主机/容器路径、启动条件、升级顺序、验证结果与恢复边界；默认不提交 Git。
